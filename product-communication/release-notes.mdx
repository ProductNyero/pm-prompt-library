# Use this prompt

Create release notes for [product/company] based on the product updates and source materials provided below.

Release / update period: [date or release period]

Reference materials: [Slack channel or messages, completed backlog items, product launch scripts, product documentation, or other relevant inputs]

Audience: [customers, users, internal stakeholders, or other audience]

Additional context: [any relevant context, messaging requirements, or constraints]

Review the reference materials to identify the product changes, improvements, fixes, and new capabilities that should be communicated in the release notes. Use the materials as the source of truth for what was actually released.

Translate the relevant changes into language appropriate for the stated audience. Focus on what changed and why it matters to the user rather than reproducing internal implementation details or project language.

Do not invent features, benefits, outcomes, release dates, or other information that is not supported by the provided materials. Where the source material does not provide enough information to accurately describe an update, request clarification rather than filling the gap with assumptions.

Return the release notes in the following structure:

**[Release title / date]**

**Highlights**

- [Most important release update]
- [Most important release update]
- [Additional update, if relevant]

**Updates**

For each relevant update:

- **[Feature / improvement name]**
- [Concise description of what changed]
- [Why it matters to the user, where supported by the source material]

**Fixes**

- [Relevant bug fix or issue resolved, if applicable]

Only include sections that contain relevant updates. Prioritise the most meaningful changes rather than attempting to include every internal change.

The final release notes should be clear, concise, audience-appropriate, and ready to publish with minimal editing.
