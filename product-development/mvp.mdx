# Build MVP

> Use this prompt to build an MVP or a prototype of your product.

## Use this prompt

Build an MVP based on the product requirements and reference materials provided below.

PRD: [paste or attach]

Reference link(s): [URL(s), if available]

Reference screenshot(s): [attach, if available]

Additional context or requirements: [any additional information, constraints, or preferences]

Use the PRD as the primary source of truth for the product's purpose, users, requirements, and expected behaviour. Use the reference links and screenshots to understand the intended experience, visual direction, interaction patterns, or other relevant characteristics.

Build the smallest complete version of the product that satisfies the requirements and allows the core user journey to work end to end. Prioritise the functionality necessary to demonstrate and validate the product's core value over secondary features or enhancements.

Where a reference is provided, learn from the relevant aspects of its experience without copying its content, branding, proprietary assets, or implementation. Adapt the useful patterns to the product defined in the PRD.

Do not add features, workflows, integrations, content, or functionality that are not required by the PRD or clearly necessary for the core user journey. Do not make assumptions about technical architecture, frameworks, platforms, APIs, or services unless they are specified in the inputs or necessary to fulfil an explicit requirement.

Where the PRD leaves a non-critical implementation detail unspecified, make a reasonable choice that supports the MVP rather than stopping for unnecessary clarification. Where an unresolved requirement would materially change the product's behaviour or scope, flag the issue before proceeding.

Ensure that the implemented experience reflects the specified user journey, functional requirements, design requirements, and expected behaviour. Handle the relevant edge cases identified in the PRD, but do not expand scope unnecessarily.

The result should be a functional MVP that can be used to experience the core product flow, not a static representation of the concept. It should be coherent, usable, and faithful to the requirements while remaining appropriately limited to MVP scope.
